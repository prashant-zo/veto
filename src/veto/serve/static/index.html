Did this release do what its pull request says, and nothing else?

Veto is a gate for Argo Rollouts canaries. It compares the canary with stable, reads the pull request, and asks Muse Spark Open to explain every difference. The AI can explain a change. It can never approve one.

Each stop is a real canary from the demo shop. The top line is Veto. The dashed line is a usual canary check that only looks at error rate and latency. Pick a release to replay it.

How it decides

Code does everything code can do. The model only answers the one question code cannot: does the pull request explain what changed?

  1. Collect. Request and call metrics from OpenTelemetry in Prometheus, logs from Loki, and the pull request behind the image tag. Canary and stable are split by their pod hash.
  2. Compact and clean. Differences become numbered evidence. Logs and PR text are cleaned, secrets are redacted, and text aimed at the reviewer is flagged. The bundle gets a hash.
  3. Floor. A loud failure, or a release that tells the reviewer to approve it, is aborted before the model runs.
  4. No intent, no decision. Without a pull request that matches the image, a person decides.
  5. Ask Muse three times. Muse Spark Open explains every evidence item against the pull request. All three runs must agree. If Baseten fails, Muse Spark 1.3 on the Meta API answers.
  6. Check the answer. A promote must explain every item, log changes must be in the diff, and no run may have seen an attack.
  7. Cap it. Any hard evidence means hold at most. Argo continues on promote, aborts on abort, and pauses for a person on hold.

Scores

Every saved release was judged several times by Veto and once by the metrics-only check. The attack suite plants prompt injections in real bundles.
